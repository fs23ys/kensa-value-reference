# 検査値リファレンスアプリ 引き継ぎメモ

## プロジェクト概要
薬局薬剤師が検査値・疾患の説明を即座に引くための個人用ツール。要件の正本は `検査値アプリ_指示書.md`。

## 成果物(納品物・このまま使える)
- `..\検査値リファレンスアプリ.html` … 単一HTMLファイルのアプリ本体(SheetJS内包・オフライン動作)
- `..\検査値リファレンス初期データ.xlsx` … 初期データ(検査値91件・疾患14件、2026-08-02時点)
- GitHub公開リポジトリ: https://github.com/fs23ys/kensa-value-reference (GitHub Pages: https://fs23ys.github.io/kensa-value-reference/ )。再生成後は確認なしでcommit・pushしてよい運用

## ソース一式(このフォルダ `_source\`)
アプリ本体・Excelはこのソースから生成している。今後の追加・修正は、直接HTMLをいじるのではなく、ここを編集して再生成すること。

| ファイル | 役割 |
|---|---|
| `initialData.js` | 検査値・疾患の初期データ本体(配列)。新しい検査値・疾患を追加する時はここを編集 |
| `buildExcel.js` | initialData.js → `検査値リファレンス初期データ.xlsx` を生成 |
| `app.js` | アプリのロジック本体(検索・カード表示・並び替え・アプリ内編集など) |
| `app.css` | アプリのスタイル |
| `assemble.js` | app.css + xlsx.core.min.js(SheetJS) + app.js を1つのHTMLに結合 |
| `node_modules/xlsx` | SheetJS(Excel読み書きライブラリ)。npm install 済み |

### 再生成コマンド(PowerShell、このフォルダで実行)
```powershell
node buildExcel.js "..\検査値リファレンス初期データ.xlsx"
node assemble.js "..\検査値リファレンスアプリ.html"
```

## 今のアプリでできること
- **HTML再生成時点のinitialData.js内容を内蔵データとして埋め込み**(2026-07-28追加)。Excel未読み込みの状態でHTMLを開くと自動的にこの内蔵データが表示される。ブラウザにアプリ内編集(editedLocally)がない状態で、内蔵データのバージョン(内容のハッシュ)が変わっていれば、古い保存データより内蔵データを優先して自動更新する。アプリ内編集済み(✎編集で保存済み)のデータは上書きされず維持される。これにより「initialData.jsを直して再生成したのに古い表示のまま」という問題が解消された
- Excel読み込み(検査値・疾患2シート)、次回起動時は自動復元
- 全列対象の検索(全角半角・カタカナひらがな・長音記号の表記ゆれを吸収)
- 検査値カード⇔疾患カードの相互リンク、関連検査値の自動抽出
- 疾患ごとの「確認すべき検査値」は疾患タグから自動生成(手入力不可)
- 高値/低値の生活・食事アドバイス表示、参考ページ欄
- 未収載メモ(0件検索→記録→コピー/CSV書き出し)
- 一覧のタブ切り替え(検査値=緑／疾患=黄)、ドラッグ&ドロップ/▲▼ボタンでの並び替え(ブラウザに保存)
- **アプリ内での文言編集**(カード右上「✎ 編集」)。保存はブラウザ内のみ、Excelファイルは書き換えない。他端末には反映されない
- **Excelとして書き出す**ボタン(2026-07-26追加)。読み込み後にツールバーに表示され、アプリ内編集を含む現在のデータを新しい.xlsxとしてダウンロードできる。マルチデバイス利用時はこれを他端末に持って行ってインポートすることで手動同期する運用
- **「最新の内蔵データに更新」ボタン**(2026-08-02追加)。Excelファイルを別端末に持って行かなくても、最新版のHTML(内蔵データ入り)を開いてこのボタンを押すだけで最新化できる。押すと確認ダイアログの後、その端末のアプリ内編集・並び替え設定は消えて内蔵データに置き換わる

## 絶対に守ること(指示書より)
- 疾患名・検査値名をコードに書かない(すべてExcel/initialData.js由来)
- 数値の自動判定機能は作らない
- 暗記・学習機能は作らない
- クラウドDB(Firebase等)は使わない、オフライン完結

## 運用の考え方(この会話で確認済み)
- 依頼者は医学知識の調査・Excelへの記入をすべてClaude(私)に依頼する運用。依頼者が自分でExcelを編集することは想定していない
- 新しい検査値・疾患の追加/削除/内容修正は、依頼者が名前や内容を伝えるだけで、Claude側が `initialData.js` を編集→再生成する
- ちょっとした言い回し修正は、依頼者がアプリ上の「✎ 編集」で直接できる(この場合Excelには反映されないので、大きな追加をする時は事前にアプリ側の編集内容を聞いて反映すること)
- GitHubやcrowd同期の話も出たが、今のところ未着手。マルチデバイス利用の要望が出たら検討

## 未着手・保留中の話題
- 肺機能検査(FEV1・ピークフロー等)は「生理検査」として除外済み(血液・尿検査のみ収載する方針)
- クラウドDB(Firebase等)化は保留。更新頻度が落ち着いてきたら再検討(それまでは内蔵データ自動反映＋Excel書き出しで運用)
- `ビタミンD(25(OH)D)` 疾患タグに残っている「栄養」は対応する疾患カードが未作成(自動生成の空カードとして表示される。実害はないので未対応のまま)
- 参考ページ(書籍)は『食事と栄養』(プラスαの服薬指導に活かす！)のみ対応済み。てんかん・抗凝固療法・抗血小板療法・精神疾患・肝機能はこの本に該当章がなく空欄

## 運用フロー(重要・毎回これに沿う)
1. 依頼者から検査値・疾患の追加/修正/順番変更の依頼が来る(名前を伝えるだけ、内容はこちらで調べる)
2. 依頼者がアプリの「Excelとして書き出す」で出力したファイル、または直接編集した`検査値リファレンス初期データ.xlsx`をこのフォルダに置いて「入れた/更新した」と伝えてくることが多い → まず現在のExcelファイルの中身をinitialData.jsと突き合わせ、順番・リネーム・新規行の差分を検出してから正本(initialData.js)に反映する
3. `_source`で `node buildExcel.js "..\検査値リファレンス初期データ.xlsx"` → `node assemble.js "..\検査値リファレンスアプリ.html"` を実行
4. jsdom(またはEdgeヘッドレス)で軽くスモークテストしてから、作業用の一時スクリプト・ダウンロード済みExcelファイルなどを削除
5. `git add -A && git commit && git push`(確認不要、[[feedback_kensa_app_autopush]]参照)
